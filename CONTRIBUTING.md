# Contributing

## Checking your environment

Before building anything, run:

```sh
python3 tools/check_prerequisites.py
```

It reports every missing prerequisite at once and exits non-zero if the tree
cannot be built yet. Several setup failures otherwise surface late and with
unhelpful messages — a missing cross preprocessor, for example, only appears as
`Error 127` from a sub-make after the legacy assembler has already built
successfully.

## First build, from a clean checkout

The steps below assume Linux. Package names are Arch's; adjust for your distro.

1. **Install the host and cross tools.**

   ```sh
   pacman -S --needed git ninja base-devel python arm-none-eabi-binutils arm-none-eabi-gcc
   ```

   `arm-none-eabi-gcc` is needed only for `arm-none-eabi-cpp`, which preprocesses
   the runtime library sources. If you would rather not install the whole cross
   compiler for one preprocessing step, set `CPP` to any C preprocessor instead:

   ```sh
   export CPP=cpp
   ```

   This is safe because the only call site passes `-undef -nostdinc`, which
   strips predefined macros and system include paths, leaving nothing
   target-specific in the preprocessing step.

2. **Install the Python packages.** A virtual environment keeps them off your
   system Python:

   ```sh
   python3 -m venv .venv
   ./.venv/bin/pip install -r requirements.txt
   ```

   Use `./.venv/bin/python` in place of `python3` for the steps below.

3. **Build and install agbcc**, in a directory beside this one:

   ```sh
   git clone https://github.com/pret/agbcc
   cd agbcc && ./build.sh && ./install.sh ../khcom && cd ../khcom
   ```

   On a recent GCC this may fail to compile: agbcc predates C99, and GCC 14 and
   newer reject implicit function declarations and implicit int conversions by
   default. Pass a more permissive compiler through `CC`. Note that `build.sh`
   expands `$CCOPT` unquoted, so `CC` must be a single token — `CC="gcc -std=gnu89"`
   makes `make` read the flags as build targets. Use a wrapper script:

   ```sh
   printf '#!/bin/sh\nexec gcc -std=gnu89 -fcommon \\\n  -Wno-implicit-function-declaration -Wno-int-conversion \\\n  -Wno-return-mismatch -Wno-incompatible-pointer-types "$@"\n' > /tmp/agbcc-cc
   chmod +x /tmp/agbcc-cc
   CC=/tmp/agbcc-cc ./build.sh
   ```

4. **Supply a base ROM.** Copy your own dump into `roms/` named for its game
   code, for example `roms/B8CE.gba`. ROMs are never committed and are listed in
   `.gitignore`. `tools/check_prerequisites.py` verifies the SHA-1 against the
   table in `README.md`.

5. **Run the remaining setup**, then build:

   ```sh
   ./.venv/bin/python tools/extract_assets.py
   ./.venv/bin/python tools/setup_legacy_toolchain.py
   ./.venv/bin/python configure.py
   ninja
   ```

   `configure.py` refuses to run until the legacy assembler exists, so keep that
   order.

## Verifying a build

The build verifies itself. `ninja` compares the linked ROM against the SHA-1 in
`decomp.yaml` and fails if they differ, so a successful build is a matching
build. On success it writes `build/<version>/verified.gba`; that file exists only
when the output matched, which makes its presence the check worth scripting
against.

To confirm the build is genuinely compiling sources rather than reusing your
base ROM, change any statement in a file under `src/`, run `ninja`, and observe
the hash assertion fail. Restore with:

```sh
git checkout -- <file>
rm -f build/<version>/verified.gba build/<version>/ok
ninja
```

## Optional components

`gbagfx` is only required for the built-mega asset paths; every `asset_gfx_*`
flag defaults to slicing the base ROM instead. Fetch it with
`sh tools/fetch_gbagfx.sh` if you need those paths. It has no standalone
upstream repository, so the script sparse-checks-out the tool subdirectory from
a pret game decompilation; override `GBAGFX_REPO` and `GBAGFX_SUBDIR` to source
it elsewhere.

gbagfx links against libpng and zlib, so their development headers must be
installed or the build stops at `png.h: No such file or directory`:

```sh
pacman -S --needed libpng zlib          # Arch
apt-get install libpng-dev zlib1g-dev   # Debian/Ubuntu
```

This only affects `tools/fetch_gbagfx.sh`. Nothing else in the tree needs libpng,
which is why `tools/check_prerequisites.py` does not treat it as required.

## Progress reporting

`tools/progress.py` summarizes an objdiff progress report and takes the report
path as an argument. The ordinary build does not emit one, so the command needs
a report produced by objdiff. Published figures live on the decomp.dev page
linked from `README.md`.

## Before opening a pull request

- Run `ninja` and confirm the build still matches for every version whose base
  ROM you have. CI builds `us`, `jp` and `eu`.
- Run `./.venv/bin/python tools/check_data_ownership.py <version>`; it should
  report `data ownership OK`.
- Keep the working tree clean of build output. Everything generated by the steps
  above is already covered by `.gitignore`.
- Note that CI runs inside a prebuilt container with the toolchain and base ROMs
  already present, so it does not exercise the from-scratch setup path described
  here. Changes to setup scripts are worth testing on a clean machine.
